## Images and CUDA

- The default image, `vllm/vllm-openai:v0.32.0`, and the default wheels are built with CUDA 13.0, as v0.31.0's; `-cu129` is CUDA 12.9, and `-ubuntu2404` variants of both are published again ("Release Artifacts", "Docker Images").
- The images compile Python bytecode at build time, for a faster start ("Build").

## Security

- Fixes GHSA-4hhp-h66f-j5j7 (chat templates validated and rendered under a timeout, `VLLM_CHAT_TEMPLATE_RENDER_TIMEOUT`), GHSA-q97c-p368-75c4 (the tokenizer's `max_token_id`) and GHSA-frvg-qw88-hww9 (P2P ZMQ sessions bounded) ("Security").
- Untrusted images are opened only in raster formats (`ALLOWED_IMAGE_FORMATS`), refusing EPS, PostScript and WMF; shared-memory multimodal cache handles are signed with an HMAC ("Security"). These close GHSA-h3rc-j82p-2c3h and GHSA-6757-hggm-hp2w, the two high advisories of v0.31.0, whose patched version is 0.32.0 (`GET /repos/vllm-project/vllm/security-advisories`).
- CORS no longer allows every origin by default; `--allowed-origins` sets them ("Security", "Breaking Changes & Deprecations").
- JSON schemas nested deeper than 64 levels answer 400 ("Security").

## Breaking changes that touch Codeman's use

From "Breaking Changes & Deprecations" and "API & Frontend", against the [vLLM settings](../../settings/vllm.md) and `src/gateway/vllm.ts`:

| Change | Effect on Codeman |
| --- | --- |
| `max_tokens` is an upper bound on the output, no longer reserved from the context window (#57035) | A long prompt is no longer refused for the `max_tokens` it asks; the gateway's tool-call probe (`max_tokens: 4096`) asks less of the context |
| Tool parsers' compatibility is checked at start (#59749) | A `tool-call-parser` that does not match the model may now fail vLLM's start, before the gateway's probe |
| Default CORS origins changed from `*` to none (#61009) | None: only the gateway calls vLLM, without an `Origin`; `allowed-origins` stays refused |
| Cascade attention removed; `--disable-cascade-attn` only warns (#61126) | None: not an accepted key |
| `mamba_cache_mode="all"` removed (#58997) | None: not an accepted key |
| Python 3.10 dropped; `transformers>=5.16.1,<5.20.0` (#60402, #57387) | None: inside the image |
| Responses API reasoning events renamed; sleep API responses standardized (#59652, #52864) | None today: Codeman uses neither |

## New parsers

- A generic `hf` tool and reasoning parser reads the checkpoint's `response_template` (#58604, #58602) ("Highlights").
- At the tag, `vllm/tool_parsers/__init__.py` adds `hf`, `plamo3` and `qwen3_json` (an alias of `hermes`), and `vllm/reasoning/__init__.py` adds `hf`, `minicpmv` and `plamo3`; neither removes a name that v0.31.0 has.

## Defaults

- A shared-memory tensor arena for multimodal tensors is on by default (`--enable-shm-tensor-arena`, #51207) ("Engine Core", "Breaking Changes & Deprecations").
- Sleep mode releases more memory: workspace scratch and the K/V cache's initialization state ("Sleep and RL").
